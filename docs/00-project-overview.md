# 00 , Project Overview & Stack Decisions

**Project:** Healthcare Appointment & Follow-up Manager (Unthinkable assignment)
**Status:** living document , updated as stages complete
**Reviewer entry point:** this file, then [01-system-architecture.md](01-system-architecture.md), then the ADR index in [adr/](adr/README.md)

## 1. What we are building (one paragraph)

A clinic booking platform with three role-based portals. **Patients** register,
search doctors by specialisation, pick an open slot, describe symptoms, and get
an AI pre-visit summary generated for the doctor at confirmation. **Doctors**
see a triage-sorted queue of upcoming visits with those summaries, and after
each visit record clinical notes + a prescription from which an AI generates a
patient-friendly post-visit summary. **Admins** manage doctor profiles,
working hours, slot durations, and leave days; marking leave on a day with
bookings auto-cancels and notifies affected patients. Every side effect that
leaves the process , emails, calendar events, reminders , goes through
persistent queues with retries, so user-facing flows never break because a
notification failed.

### Depth upgrades , strengthening the graded axes (no scope growth)

Adopted instead of feature breadth: these deepen the four explicitly graded
mechanics using only infrastructure the brief already requires.

| Upgrade | Serves |
|---------|--------|
| Runnable **concurrency-proof script** (`server/scripts/concurrency-proof.mjs`): N simultaneous confirms → exactly one wins; output captured in README | "Problem-solving for slot conflicts" made demonstrable, not just claimed |
| **Leave preview endpoint** (`GET …/leave-preview?date=`) returning affected-booking count before commit; admin UI shows it before confirming | Leave-conflict handling visible and deliberate |
| **State-transition audit trail** (`appointment_events`: from/to status, actor role, reason incl. `leave:<id>` cascade) written in the same transactions | Concrete evidence for the 800-word write-up instead of prose claims |
| **Async LLM lifecycle**: summaries start `pending`, tick worker retries via the same claim/backoff pattern as email, deterministic fallback after cap; booking never blocks on LLM at all | Reliability pattern reused across two subsystems; "LLM failures handled gracefully" shown structurally |
| **Admin notification-health view**: pending/failed/dead-letter counts from the outbox | Notification reliability demonstrated live, not asserted in README |
| **Hold countdown** in the booking wizard (native polling) | Visualizes the hold mechanic the write-up explains |

### Deferred extensions , designed, deliberately not built (see [ROADMAP.md](ROADMAP.md))

Dependent bookings, multi-channel notifications (SMS/WhatsApp), waitlist,
summary languages, voice input, queue-position display, refill requests.
Each has a design sketch recorded in ROADMAP.md; all were cut because the
submission guidelines demand strictly-required dependencies only and the
evaluation focus names depth on specific mechanics, not breadth. Nothing here
is required by either PDF; nothing graded is weakened by their absence.

## 3. Stack decision matrix

Chosen cells are justified individually in the referenced ADRs; this table is
the map of what was considered and why the winner won.

| Axis | Chosen | Runner-up | Also considered | Why chosen won |
|------|--------|-----------|-----------------|----------------|
| Runtime | Node.js 20 + ESM | Deno/Bun | Python/FastAPI | JS shares language across stack; ecosystem fit for the integrations being graded |
| Web framework | Express 4 | Fastify | NestJS, Next.js API routes | Ubiquitous, zero-magic; serverless rejected (jobs) , [ADR-0004](adr/0004-express-monolith-over-serverless.md) |
| Database | PostgreSQL (Neon free tier) | SQLite | MongoDB Atlas | Partial unique index = provable double-booking prevention , [ADR-0002](adr/0002-postgresql-over-mongodb.md) |
| Data access | Raw SQL via `pg` | Drizzle | Prisma, Knex | Constraints stay visible; minimal deps per guidelines , [ADR-0003](adr/0003-raw-sql-over-orm.md) |
| Migrations | Plain `.sql` files + tiny runner | node-pg-migrate | Prisma migrate | Forward-only, reviewable as schema truth |
| Auth | JWT (sub+role) in httpOnly cookie | Sessions | Passport, Auth0 | Simplest full role-based story without infra , [ADR-0005](adr/0005-jwt-httponly-cookie-auth.md) |
| Validation | zod at boundaries | hand-rolled | Joi | One small dep; errors map cleanly to API problem responses |
| Email | Nodemailer + SMTP | SendGrid API | Mailgun | No vendor account needed (Gmail app-password / Ethereal dev); queue owns retries |
| Calendar | Hand-rolled OAuth2 + REST via fetch | `googleapis` SDK | Calendly-style embeds | Cuts the heaviest dep; shows the integration explicitly , [ADR-0007](adr/0007-handrolled-google-calendar-rest.md) |
| LLM | Provider-agnostic adapter over fetch (`openai`/`gemini`/`none`) | `openai` SDK | LangChain | Own the failure ladder; runs keyless in fallback mode , [ADR-0006](adr/0006-provider-agnostic-llm-via-fetch.md) |
| Jobs | `node-cron` in-process + `/jobs/tick` | BullMQ+Redis | Vercel Cron | Idempotent single tick; survives free-tier sleep , [ADR-0008](adr/0008-inprocess-scheduler-with-tick-endpoint.md) |
| Frontend | React 18 + Vite SPA | Next.js SSR | EJS templates / vanilla JS | Component model fits 3 portals; Vite build served statically by Express |
| Styling | Hand-written design system (CSS custom properties) | Tailwind | MUI/AntD | Distinctive identity per design brief; no utility-class noise in review |
| Tests | Vitest + supertest | Jest | Playwright e2e | ESM-native, fast; HTTP-level integration tests cover the graded behaviors |
| Deploy | Render web service (free) | Railway | Vercel | Long-running process support; keep-alive documented |

### Dependency budget (server)

```
express, pg, bcryptjs, jsonwebtoken, zod,
node-cron, nodemailer, dotenv
```

Eight runtime dependencies. Everything else , Google Calendar calls, LLM calls,
retry/backoff, migration running , is ~a few hundred lines we own and can
explain line-by-line in review.

## 5. Non-goals (explicit scope cuts)

Recording these stops scope creep *and* tells the reviewer the boundary was
chosen deliberately:

- Multi-clinic tenancy , single clinic assumed; all datetimes are clinic-local.
- Payments, insurance, medical records storage.
- SMS/push/WhatsApp channels , email covers the brief; multi-channel design preserved in ROADMAP.md.
- Real-time (WebSocket) queue updates , polling is proportionate.
- i18n, accessibility beyond WCAG-baseline focus management and semantics.
